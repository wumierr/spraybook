## 四、整合方式：一套数据库，双向链接

核心原则：一套 SQLite 数据库从零建；计算器和记账系统共用；**作业单（jobs）是纽带**；计算器写执行数据，记账系统写财务数据；不跨层写表。

数据流：现场作业 → 计算器录入 → 写入 jobs+子表 → 记账系统读取 → 生成 settlements+bills+journal_entries → 登记收款/付款/预支/预收 → 更新客户财务状态 → 计算器下次读取（历史+财务状态）→ 闭环。

### 数据库五层

| 层 | 表 | 谁写 | 谁读 |
|---|---|---|---|
| 主数据 | parties, plots, chemicals, equipment, price_rules | 两边都可维护 | 两边都读 |
| 作业执行 | jobs 及子表 | **计算器写** | 记账读 |
| 结算财务 | settlements, settlement_items, bills, receipts, payments, advances | **记账写** | 计算器读状态 |
| 复式记账 | accounts, journal_entries, journal_lines | **记账写** | 记账读 |
| 导入复核 | import_batches, raw_import_rows | 记账写 | 记账读 |

关键约束：计算器只写作业执行层；记账系统不修改作业执行数据（只读）；记账系统只写结算财务层和复式记账层；两边都读主数据。

## 五、产品最终全貌

**一句话定位**：一个面向小型植保飞防队的"现场作业计算 + 财务记账"一体化系统：现场用计算器算药、算水、算趟数、出工单；后台用记账系统消费工单、出账单、记收支、管预支预收、导入历史账、算盈利。一套 SQLite，两个入口，作业单是纽带。

系统架构：现场端（手机/平板，已有）+ 后台端（Web/桌面，新建）→ API 层（共用后端）→ 一套 SQLite 数据库（五层）。

## 六、用户体验流程

### 已有流程：现场打药/吊运（飞手，不改）
选客户/新建 → 确认参数 → 药量/水量/趟数 → 多农户分家 → 飞行组 → 完成量标记 → 电池记录 → 生成每户工单草稿 → 确认提交写入数据库（离线可暂存）。吊运：作业完成输入斤数 → 按单价算钱 → 生成工单 → 提交。

### 新增流程：后台记账（记账人，此次核心）
1. 看今日/待结算工单；2. 复核工单执行数据；3. 生成结算单、账单（药钱、作业钱、凑药、包药/不包药）；4. 登记收款；5. 登记支出（油费、药费、维修、吃饭、设备花费）；6. 登记预收、预支；7. 系统自动生成复式分录，检查借贷平衡；8. 看盈利汇总。
导入历史：9. 上传 Excel → LLM 抽取 → staging；10. 人工复核待确认项；11. 确认后写入正式表；12. 保留原始 sheet、行号、原文。
查询：13. 客户欠款、预收余额；14. 按作业/客户/月的盈利；15. 设备效率、电池循环；16. 农户偏好。

### 新增流程：计算器反哺（自动）
下次现场作业时，计算器自动带出：该客户历史用药、历史价格；预收余额、欠款；是否包药、是否凑药；上次结算状态。

5. 计算器下次能带出财务状态
6. 不改计算器核心逻辑
7. 一套 SQLite，两个入口，作业单是纽带
